# mabo-ctl — Deep Audit + Penetration Test

**Date:** 2026-08-27
**Target:** `github.com/maborak/mabo-ctl` @ `5deb4fa` (working tree dirty)
**Scope:** whole repository (~41.5k LOC Go, 14 packages), weighted toward the uncommitted extensions wave
**Method:** 6 parallel static specialists + 1 live red-team engagement + 1 blue-team detection pass, every HIGH+ independently re-verified by the coordinating thread
**Audience:** this document is written to be *checked*, not trusted. Every finding carries a file:line anchor and a reproduction command. §9 is a verification checklist for a reviewing model.

## 1. Executive summary

| Severity | Count |
|---|---|
| 🚨 CRITICAL | 1 |
| 🔴 HIGH | 4 |
| 🟡 MEDIUM | 6 |
| 🟢 LOW | 4 |

**The one-line risk:** the codebase's security posture is genuinely strong — every classic attack class the tool is exposed to was attempted live and *blocked* — but its **process-identity** and **hook-lifecycle** guarantees are weaker than the code's own comments claim, and one shipped feature (`tty: true`) has never worked on any platform.

Two results deserve to be stated up front because they are unusual:

1. **The live attack surface held.** Path traversal, template escape, config-discovery escape, PID-file poisoning with malformed values, `reset` blast radius, `open` argument injection, and the entire web-console matrix (CSRF, DNS rebinding, token bypass, XSS, SSE injection) were all attempted against a real binary and all refused. This is not a codebase where the obvious things are broken.
2. **What did break, broke in the gap between a stated invariant and its implementation.** Three of the top four findings are cases where a doc comment asserts a guarantee that the adjacent code does not actually provide.

## 3. 🚨 CRITICAL

### C-1 — A `pre_start` hook runs unbounded while holding the cross-process start claim

**`internal/supervisor/supervisor.go:1098`** · `[uncommitted]` · CWE-833 (deadlock) / CWE-400

```go
if len(in.Hooks.PreStart) > 0 {
    herr := s.runHook(ctx, in, in.Hooks.PreStart, logFile)   // bare caller ctx — no deadline
```

The other three lifecycle hooks are bounded. `runStopHook` at **`supervisor.go:987`** wraps them:

```go
hookCtx, cancel := context.WithTimeout(ctx, s.stopGrace())
```

`pre_start` gets no such wrapper. It runs while `startOne` holds **both** the per-service mutex (`:1011`) and the **cross-process start CLAIM** taken at `:1049` via `state.ClaimPID`. That claim is only cleared as stale when the owner is dead or the claim is older than ten minutes — and a mabo-ctl blocked inside a hook is very much alive, so neither condition fires.

Two of the three front ends supply no deadline of their own:

| Front end | Context | Bounded? |
|---|---|---|
| CLI | `interruptible()` — `cmd/mabo-ctl/main.go:269` | cancels on SIGINT only |
| TUI console | `newOp()` — `internal/console/stream.go:224` | `context.WithCancel(context.Background())` |
| `serve` | `mutate()` — `internal/web/handlers.go:468` | ✅ `opTimeout()` |

**Failure scenario.** A `pre_start:` hook that hangs — a bad script, a wait on a network resource, a read from stdin — blocks `mabo-ctl start backend` indefinitely. **Every other terminal's `start backend` then fails with `ErrClaimed` for up to ten minutes**, with no message distinguishing "a hook is running" from "a mabo-ctl is wedged." No event is emitted before the hook call, so the operator sees `starting…` and then silence.

This directly contradicts the multi-terminal contract in `AGENTS.md` ("a second invocation from a different terminal knows what the first one started").

**Reproduced:** a second owner calling `state.ClaimPID` 300 ms into a 2 s `pre_start` hook is refused with `ErrClaimed … has been starting it since …`.

## 4. 🔴 HIGH

### H-1 — `stop` kills a foreign process that merely happens to be a group leader

**`internal/supervisor/signal_unix.go:56`** · `[committed]` · CWE-367 / CWE-1188 · CVSS 6.3 `AV:L/AC:H/PR:L/UI:N/S:U/C:N/I:H/A:H`

`verifyGroup` performs two checks: `pgid > 1`, and `pgid == pid`. Its own doc comment reasons:

> every process we spawn is a group leader by construction, so a live pid whose group id differs is definitionally not ours

That is true — and it is the **converse** that the code relies on and that does not hold. `pgid == pid` does not mean the process *is* ours. Every `setsid`-launched process is its own group leader: a tmux pane leader, a container init, a `systemd --user` child, another supervisor's supervised process.

`state.PIDRecord.StartedAt` (**`internal/state/state.go:147`**) is persisted, and is read for uptime (`supervisor.go:561`), exit correlation (`exit.go:109`) and supersession (`supervisor.go:729`) — but it is **never compared against the OS process's real start time** before `signalGroup` fires at `supervisor.go:1321,1344`.

**Reproduced twice independently.** Second run used a deliberately stale record:

```
$ cat .dev/pids/victim.pid
{"pid":45963,"started_at":"2020-01-01T00:00:00Z"}

$ ps -o pid=,lstart= -p 45963
45963 Thu 27 Aug 20:42:32 2026          # six years after the recorded spawn

$ mabo-ctl stop victim
victim  stopping… (pid 45963, group 45963)
victim  ○ stopped   stopped

$ ps -p 45963   →   dead
```

The evidence that would refute the identity claim is **already on disk and already in the struct**. It is simply never read on the signalling path.

### H-2 — `tty: true` has never worked, on any platform

**`cmd/mabo-ctl/attach.go:91-100`** · `[committed]` · functional, not security

The hidden broker subcommand is registered with `Args: cobra.ArbitraryArgs` but **without** `DisableFlagParsing: true`. `ArbitraryArgs` bounds positional-argument *count*; it does not stop flag parsing. Cobra therefore rejects the broker's own flags before `RunE` is ever reached:

```
$ mabo-ctl internal-tty-broker --log /…/x.log --sock /…/x.sock -- /bin/sh -c 'sleep 1'
error: unknown flag: --log
```

The parent (`internal/supervisor/tty_broker.go:79`) pipes the child's **stderr** into the handshake pipe, so it JSON-unmarshals cobra's error line. The operator sees:

```
$ mabo-ctl start ttysvc
ttysvc  ✕ failed    terminal broker handshake: invalid character 'e' looking for beginning of value
```

`DisableFlagParsing` appears exactly once in the entire repository, and it is `false` (`cmd/mabo-ctl/tools.go:362`).

**Why it shipped:** `ttyBrokerExecutable` is a package var (`tty_broker.go:29`) that tests replace with "a well-behaved fake." The real cobra dispatch path has no test at all.

**Second, latent bug stacked behind it.** Nothing ever creates `.dev/tty/`. `state.New` (`internal/state/state.go:86`) `MkdirAll`s only `.dev/`, `logs/`, `pids/` and `exits/`, and there is no other `os.Mkdir*` anywhere in `internal/` or `cmd/`. So even once the flag bug is fixed, `net.Listen("unix", <root>/.dev/tty/<svc>.sock)` (`tty_broker.go:181`) will hit `ENOENT` on Linux.

**Third, a swallowed diagnostic.** On darwin, `openPty` (`internal/supervisor/tty_darwin.go:17`) declines with a genuinely helpful message — *"tty terminals are not yet supported on darwin … declare tty: false and use mabo-ctl exec instead"* — which the operator never sees, because the process dies at the cobra layer first.

### H-3 — `pre_stop` prepends its full runtime to the stop budget, silently

**`internal/supervisor/supervisor.go:1333`** · `[uncommitted]`

```go
s.runStopHook(ctx, in, in.Hooks.PreStop, ev, "pre_stop")     // :1333
emit(ev, Event{... "stopping… (pid %d, group %d)"})          // :1335
...
if err := signalGroup(pgid, termSignal); err != nil {        // :1344
```

The hook runs **before** the `"stopping…"` event and **before** SIGTERM, and `stopOne` holds the per-service lock for the whole body (`:1279`). Consequences:

- The hook is bounded by `stopGrace` (default **10 s**, `supervisor.go:376`), so a slow `pre_stop` nearly **doubles** total stop time to ~20 s — contradicting the `AGENTS.md` contract *"Stop kills the process GROUP, SIGTERM → grace → SIGKILL."*
- The operator sees **nothing at all** between issuing `stop` and the hook returning.
- Any concurrent `stop`/`restart`/`start` of the same service from another terminal blocks on the lock for the hook's full duration.

**Measured:** a 1.5 s `pre_stop` hook made `Stop()` on an otherwise instantly-dying service take **1.99 s** wall clock.

`TestStopHooksRunAndCannotBlockTheStop` (`internal/supervisor/hooks_test.go:107`) asserts only that the hook ran and the process died. It never measures timing, so this class has no coverage despite the test's name asserting the opposite property.

### H-4 — A non-loopback `health:` host is accepted, probed forever, and never announced

**`internal/health/health.go:363`** + **`internal/config/validate.go`** · `[committed]` · CWE-918

`checkURL` enforces a scheme allowlist (http/https), requires a non-empty host, refuses redirects (`health.go:107`), never reads the body, and bounds each probe at 2 s. It does **not** check that the host is loopback, and `grep -rn "IsLoopback" internal/config internal/health` returns only doc text and examples — the check exists nowhere.

Nothing anywhere prints a warning when `health:` resolves off-box. Combined with §6's finding that the console logs nothing, the operator has no way to answer *"did this config just make my machine start calling out to the internet?"*

The config author already has code execution under the accepted trust boundary, so this is not a novel RCE path. It is an **ungated egress destination with zero observability**, which is a separate property and the one the channel contract requires.

## 5. 🟡 MEDIUM

### M-1 — Lifecycle hooks resolve `argv[0]` via ambient PATH, breaking the runtime invariant

**`internal/supervisor/supervisor.go:961`** · `[uncommitted]` · CWE-426 / OWASP A05

```go
hook := exec.CommandContext(ctx, argv[0], argv[1:]...)
hook.Env = in.Env                                        // does NOT redirect resolution
```

`AGENTS.md` and `internal/service/service.go:21` both state that runtime resolution **never** falls back to an ambient PATH lookup. `cmd[0]` earns that: `build()` rewrites it to an absolute path via `resolveRuntime` (`internal/service/service.go:334-337`), and `Instance.Cmd`'s doc says *"an absolute path to the executable chosen by Runtime, never a bare name left to the child's PATH."*

`runHook` never goes through the resolver, and Go's `exec.Command` performs its implicit `LookPath` against the **invoking process's live `PATH`**, not `cmd.Env` — so setting `hook.Env` does not help.

The attacker is not the config author. It is a hostile local uid or a previously-compromised tool that can place a same-named binary earlier in the developer's `PATH`. A config declaring `hooks: {pre_start: [npm, run, migrate]}` inherits whatever `PATH` resolves that day.

### M-2 — `lsof` is PATH-resolved, and *every* failure reads as "port free"

**`internal/supervisor/portholder.go:91`** · `[committed]` · CWE-426 / CWE-1188

```go
cmd := exec.CommandContext(ctx, "lsof", "-nP", "-iTCP:"+strconv.Itoa(port), "-sTCP:LISTEN")
out, err := cmd.Output()
if err != nil {
    return Holder{}          // "free" — for ENOENT and EACCES just as much as exit-1
}
```

There is no `exec.LookPath("lsof")` anywhere in the repository and no `preflight`/`doctor` check for its presence. On a host without `lsof` — a slim container, a minimal Linux image — the port-conflict guard is **off for every service, permanently and invisibly**.

This is the same failure mode the project already diagnosed and fixed for context cancellation. The comment at `supervisor.go:833-838` explains that a dead context made "every port read back as free," turning the guard off, and mabo-ctl "then spawned a second copy of a service onto a port another process already held." The ctx path was closed. The missing-binary and PATH-shadowed paths were not.

### M-3 — The web console records nothing, on any branch

**`internal/web/server.go:577`** · `[committed]`

```go
ErrorLog: log.New(io.Discard, "", 0),
```

`guard()` (`internal/web/security.go:83-104`) contains no logging call on any path, accepted or refused, and grep finds no `log.`/`Printf`/`Fprintf` in `security.go` or `handlers.go`. Every refused CSRF, rebinding and bad-token attempt against the one network surface is invisible — and so is every accepted one.

The guards themselves are excellent (§7). The problem is purely that a successful probe and a blocked attack are indistinguishable afterwards, because neither leaves a trace.

### M-4 — Raw ANSI/OSC escape sequences pass from child stdout to the terminal unmodified

**no sanitising layer exists** between `internal/state`'s log write and `cmd/mabo-ctl`'s `logs`/`tailf` render · `[committed]` · CWE-150/117 · CVSS 4.2 `AV:L/AC:L/PR:N/UI:R/S:C/C:N/I:L/A:N`

A child emitting OSC-8 hyperlinks, OSC-52 clipboard writes and `\r` overwrites produced byte-identical `1b 5d 38 3b …` and `1b 5d 35 32 3b 63 …` sequences in both `.dev/logs/ansi.log` and `mabo-ctl logs` stdout. No stripping, no cap.

Identity is the **compromised supervised child** — a corrupted dependency inside an otherwise-innocent `cmd:`. Config authorship is not required, so this sits outside the accepted trust boundary. A dev server can rewrite the operator's terminal, hide log lines, or attempt a clipboard write the moment `logs` is run. Raw passthrough is partly intentional (dev servers emit colour), but there is currently *zero* mitigation and no opt-out.

### M-5 — `tty_broker` writes under `.dev/` directly, and opens the repo's second listener

**`internal/supervisor/tty_broker.go:180,181,187,217`** · `[committed]`

```go
os.Remove(sockPath)
ln, err := net.Listen("unix", sockPath)
_ = os.Chmod(sockPath, 0o600)          // AFTER listen — the socket exists at umask perms first
```

Two stated invariants are broken:

- *"Writes under `.dev/` come only from `internal/state`."* `state.go:265` only **names** the path (`TTYSockPath`); it does not own the create, chmod or remove. Contrast the extensions wave's own hook logging, which correctly routes through `s.st.OpenLogAppend`.
- *"`internal/web`'s listener is the only one in the repo."* False as written — this is a second `net.Listen`. It is a Unix domain socket for local PTY IPC, not a network surface, but the invariant is stated absolutely.

Note also the ordering: `Chmod(0600)` runs *after* `net.Listen`, so the socket briefly exists at `0777 & ~umask`. Low impact under a normal `0022` umask (no write bit for others ⇒ no connect), but it is a window that need not exist. Currently unreachable in practice because of H-2.

### M-6 — Clearing a stale claim is silent

**`internal/state/state.go:328-344`** · `[committed]`

A refusal names the holder's pid and timestamp (`state.go:338`, `supervisor.go:1050`). **Clearing** stale wreckage emits nothing on any branch. An operator cannot distinguish a clean start from "I just evicted another mabo-ctl's in-flight claim" — which, given C-1, is exactly the situation that will arise in practice.

## 8. Corrections to standing project assumptions

Three claims in the project's own documentation and briefs were tested and found wrong. Each is worth fixing at the source.

1. **"A start destroys the previous log."** False. Truncation **rotates to `<log>.1`**, keeping one prior generation (`internal/state/state.go:410-429`). One generation of evidence survives a restart. The new `--grep`/`--since` filters are read-time only and never touch the stored file.
2. **"`internal/web`'s listener is the only one in the repo."** False as written — see M-5.
3. **"Every output channel redacts through `internal/redact` at the source."** True for everything mabo-ctl *composes*. Child stdout in `.dev/logs/*.log` is not redacted, but that is the child's own output, and the behaviour is consistent across CLI, JSON and log channels — **no channel is worse than another**. Not a finding; worth stating precisely so it is not re-reported every audit.

## 10. Remediation priority

No fixes were applied. This is a findings document; the fix step is a separate decision.

1. **C-1** — wrap the `pre_start` hook in a timeout, as `runStopHook` already does. One-line shape, removes a multi-terminal denial-of-service.
2. **H-1** — compare `PIDRecord.StartedAt` against the process's real start time in `verifyGroup` before signalling. The data is already there.
3. **H-2** — set `DisableFlagParsing: true` on the broker command; create `.dev/tty` in `state.New`; surface the broker's JSON `Err` field instead of letting stderr poison the handshake. Add a test that exercises the real dispatch path rather than the fake.
4. **H-3** — run `pre_stop` under its own budget outside the stop budget, or at minimum emit the `"stopping…"` line *before* the hook so the operator sees why nothing is happening.
5. **M-2** — probe for `lsof` once at startup and distinguish "no holder" from "lookup failed." A guard that fails open should say so.
6. **H-4 / M-3 / M-6** — the observability trio: warn on a non-loopback `health:` host, log console requests (accepted and refused), and emit an event when a stale claim is cleared.
7. **M-1** — route hook `argv[0]` through `resolveRuntime`, or document explicitly that hooks are PATH-resolved and `cmd:` is not.
8. **M-4 / M-5 / L-\*** — escape-sequence policy, `.dev/` write ownership, and the documentation corrections in §8.
